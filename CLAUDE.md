# CLAUDE.md

Tao Te Ching · Tao of Power: an interactive tool for exploring the Tao Te Ching
(Daodejing). A reader draws one of 81 passages with a virtual 64-stick method,
reads a new English rendering with tap-to-open notes on the Chinese, answers
questions, and writes a journal. Live at https://tao.tensor.group (Cloudflare).
The main user reads on a phone, in the Brave browser. Test at phone width.

## Commands

```sh
npm run serve        # static server for app/ at http://localhost:5173
npm test             # node --test tests/*.test.js (draw, journal, markup)
npm run check        # content check + copyright guard + art check
node scripts/check-content.mjs --all   # also requires all 81 passage files
npm run precache     # rewrite the service-worker file list and version in app/sw.js
npm run build        # merge lexicon, build text/index/strokes, then precache
npm run deploy       # build + check + wrangler deploy (Worker + assets; needs Cloudflare login)
npm run dev          # wrangler dev on http://localhost:8787 with local D1 (Worker + passkey sync; vars in .dev.vars)
scripts/analytics.sh 7   # usage report from D1 (last 7 days)
```

Run `npm test` and `npm run check` before you say a change is done. Run
`npm run precache` after any change under `app/`, or the installed PWA keeps
the old files.

## Layout

- `app/` is the whole site. There is no bundler and no framework: plain ES
  modules, hash router (`#/`, `#/p/N`, `#/browse`, `#/journal`, `#/about`, `#/how`).
  - `js/app.js` router, app state, service-worker update flow.
  - `js/ui.js` `h()` DOM helper. Text goes in through `textContent` only.
  - `js/sheet.js` bottom sheet (notes drawer) with a back stack and pull-down to close.
  - `js/notes.js` `[[text|noteId]]` markup, character sheets, note kind labels.
  - `js/journal.js` localStorage journal: entries, draws, tombstones, merge-safe import/export, drafts.
  - `js/margin.js` margin tabs: journal entries with `at: { key, snip }`, pinned beside page blocks marked `data-mark`.
  - `js/draw.js` stick-draw logic (crypto random). `js/brush.js` stroke-by-stroke calligraphy.
  - `js/views/*` one module per page.
  - `data/passages/NN.json` one file per passage (rendering, notes, lenses, plates, questions).
  - `data/lexicon.json` is generated: `lexicon-add/merged/*.json` merges into it (`scripts/merge-lexicon.mjs`).
  - `data/text.json`, `index.json`, `strokes/` are generated by `scripts/build-*.mjs`.
  - `sw.js` precache block is generated. Do not edit between the `<precache>` markers by hand.
- `sources/` pinned public-domain inputs (Wang Bi Chinese text, Legge 1891, Unihan, Shuowen).
- `scripts/` build and check scripts. `tests/` node:test unit tests.
- `docs/content-style.md` binding rules for every file in `app/data/`. `docs/creation-brief.md` how to write a passage file.
- `docs/superpowers/` design spec and plan.

## Rules

- **Copyright.** R. L. Wing's *The Tao of Power* (1986) inspired the app. It is
  copyrighted. Never copy, paraphrase line by line, or reconstruct its wording
  or any other modern translation. Shipped English is new, written from the
  Chinese. `scripts/copyright-guard.mjs` checks n-gram overlap against local
  book files. These folders are git-ignored and must never be committed or
  opened by content writers: `Tao of Power/`, `taoofpower/`,
  `google-books-images/`, `docs/study/`, `sources/raw/`.
- **Content.** Read `docs/content-style.md` before you edit any data file. Key
  points: Chinese first; no invented scholarship (Shuowen quotes must exist in
  `sources/shuowen.txt`); hedge Mawangdui and Guodian readings as "reported";
  no added subjects or intensifiers in renderings; paired opposites are
  related, not ranked (§10); every passage has 2–3 `questions` (§11).
- **Note kinds** must be one of: etymology, gap, history, geopolitics,
  wordplay, variant, wangbi, legge, practice, pair. Add a new kind in three
  places: `content-style.md`, `scripts/check-content.mjs`, and `KIND_LABEL` in `app/js/notes.js`.
- **Security.** The CSP in `index.html` allows only same-origin, plus
  Cloudflare Web Analytics (`static.cloudflareinsights.com` script,
  `cloudflareinsights.com` connect). No inline scripts or styles, no other
  external fonts or CDNs, no `innerHTML`.
- **Analytics.** `worker/index.js` serves `./app` and answers `POST /api/e`,
  storing anonymous events in D1 `tao-analytics` (schema in
  `worker/schema.sql`). The client is `app/js/track.js`: route views plus a
  few named actions; never typed text, journal content, IPs, or UA strings;
  off under DNT/GPC. The Worker also drops DNT/GPC, foreign-origin, and
  over-`EVENTS_LIMIT` events (it fails open without that binding). Report: `scripts/analytics.sh [days] [--local]`. A new
  event name must be added to `EVENTS` in the Worker.
- **DOM.** Build nodes with `h()`; replace children with `fill()` from `ui.js`. Native `replaceChildren()`/`append()` print
  `null` as the text "null"; filter nulls or pass the children through `h()`.
- **Journal data** lives in the user's browser, and on the server only when
  the reader turns on sync. Keep the export format backward compatible:
  `validate()` must accept old files, and new entry fields must be optional.
- **Sync** (optional, passkey): `worker/sync.js` serves `/api/auth/*`,
  `/api/session`, `/api/journal/sync`, `/api/account` from D1 `tao-sync`
  (schema `worker/sync-schema.sql`). The server merges with the same
  `merge()` as the browser; `lastExportAt` never leaves the device. Client:
  `app/js/sync.js` (single-flight sync after each save, on tab focus/hide, and
  online) and `app/js/views/sync-ui.js` (card after a draw, Sync section on the
  Journal page). Removals sync as tombstones (entries and draws). Never log or
  echo journal text. A missing rate-limit binding answers 503 (except with
  `RP_ID` localhost). Each sync and delete names its account; a missing name
  is accepted for old installed clients, a wrong one gets 409. Rate-limit
  namespace ids are per Cloudflare account: Tao uses 4111–4114. `npm run dev` is the only way to test passkeys locally
  (RP ID `localhost`).
- **Art** (`app/data/art.json`, `app/art/`): public domain or CC0 only, from
  Wikimedia Commons or the Cleveland Museum of Art / Art Institute of
  Chicago open-access collections (`scripts/check-art.mjs` enforces this, and
  260 KB per file). When provenance is weak, keep the image and say so in
  `collection` and the look-text ("said to be", "as reported"). Captions quote
  our own renderings, never another translation.
- **Search** (`#/search`) runs in the browser: `app/js/search-core.js` (BERT
  WordPiece + mean of 4-bit static token vectors from `app/model/`, vendored
  once by `scripts/vendor-search-model.py` from Model2Vec potion-retrieval-32M,
  MIT) plus a keyword bonus. `scripts/build-search.mjs` (part of `npm run
  build`) embeds every passage, note, question, plate, story, artwork, echo,
  glossary term, and Wing note into `app/data/search/`. The same JS code embeds
  queries and documents; `tests/fixtures/wordpiece.json` pins tokenizer parity
  with the reference tokenizer. Model, search index, and art are cached on
  first use by `sw.js`, not precached. Rebuild the index after content changes.
- **About map** data (`app/data/map.json`) is built once by `python3
  scripts/build-map.py <dir>` from Natural Earth 1:50m land and rivers
  (public domain); places and dynasty facts live in `app/js/views/about.js`.
- **Pronunciation**: `app/audio/<syllable>.mp3` (audio-cmn, Chen Wang, CC BY-SA)
  for the readings in the lexicon; `python3 scripts/vendor-audio.py` adds new
  ones and rewrites `app/audio/index.json`. `app/js/audio.js` maps pinyin to a
  file (same rule as the script) and falls back to speechSynthesis.
- **Rare characters** (outside the BMP) are drawn from GlyphWiki outlines in
  `app/data/rare-glyphs.json`; run `python3 scripts/vendor-rare-glyphs.py`
  after adding content. They render as plain glyphs, not dictionary buttons.
- **Gallery thumbnails** live in `app/art/thumbs/`; run `python3
  scripts/make-thumbs.py` after adding art (check-art requires them).
- Light theme is the default. Every color comes from the CSS custom
  properties in `app/css/app.css`, which also define the dark theme.
